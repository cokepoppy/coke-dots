OpenAI Dots 产品调研报告

调研日期： 2026 年 10 月 9 日
范围： OpenAI Dots 产品、功能清单、优缺点，以及与 Meta Muse、Manus Cue、SpaceXAI/xAI Grok Bot 的比较。
资料口径： 优先引用产品方官方公告和官方帮助文档。产品能力、开放范围和路线图均按官方资料分别标记；未公开的价格、配额和效果不作推断。本报告不是基准测试或实机评测。

一、结论摘要

OpenAI Dots 把 ChatGPT 从“用户每次发起一轮问答”扩展为“长期在线、能保留个人工作上下文、可以在自己的云端电脑上持续做事的 Agent”。它的产品组合包括持久记忆、后台主动研究、云电脑与浏览器、4,000 多个应用连接、跨 ChatGPT/Slack/Teams 的沟通入口、任务进度与审批控制，以及面向企业的专用 Dots 预览。

Dots 的主要优势是把模型、ChatGPT 上下文、应用连接、云端执行和风险控制放进同一个产品入口。它与 Meta Muse 的大众个人生活助理定位重叠；与 Cue 的专属 Agent 身份和支付/电话/邮箱能力重叠；与 Grok Bot 的常驻云电脑、多 Bot 协作和长任务执行重叠。竞争关键因此不只是模型能力，也包括连接器覆盖、持续任务成功率、审批体验、权限边界和用户信任。

截至调研日，Dots 仍处于分批开放阶段。官方说明首个 Dot 随 Pro 或 Business Premium 计划提供；Enterprise、Edu、Healthcare 可由管理员开启 Beta。开放国家/地区、深度任务用量额度和不同工作负载的上限没有在公告中给出统一数字。企业专用 Dot 仍属定向试点，短信入口及多 Dot 团队协作是规划或后续方向，不能按普遍可用功能计算。OpenAI 产品公告

二、产品定位

OpenAI 将 Dots 定义为 ChatGPT 中的常驻 Agent：用户设定目标和边界，Dot 记住偏好与工作背景，在用户不在线时继续处理任务、检查已连接信息，并在需要决定或授权时回到用户这里。它可以通过对话接任务，也可以保留持续责任，而非每次从空白会话开始。

产品叙事有两个层次：

  1. 个人 Dot： 由个人命名和定制，跨会话保留上下文，处理研究、规划、内容、分析和网页操作等工作。
  2. 组织专用 Dot： 为采购、发票处理、客服等明确岗位配置身份、凭据和系统访问权限；当前处于企业试点阶段，并计划接入 Microsoft Agent 365 的治理能力。

OpenAI 公告称 Dots 使用 GPT-6 Astra，每个 Dot 有自己的云电脑，能通过插件生态连接 4,000 多个应用。这里的“4,000 多个”是官方公告中的平台口径，不代表每个连接器都支持相同读写权限或自动化深度。OpenAI：Introducing dots

三、功能清单

能力 用户可以做什么 当前状态与边界
持续个人助理 命名和定制主要 Dot；通过反馈让它逐步贴合偏好、目标和质量标准 主要 Dot 正在逐步开放；官方尚未把“团队拥有多个 Dot”作为普遍可用功能
跨会话记忆 Dot 使用当前任务上下文、相关 ChatGPT Memory 和自己保存的工作笔记；可以保留偏好、决定和持续责任 Dot 自己的笔记与 ChatGPT Saved Memory 分开；不是完整对话记录，也不意味着所有上下文都会自动进入每次任务
云电脑和浏览器 在独立云电脑中操作网站和应用；用户可以查看运行状态、接管鼠标键盘，再把控制权交还给 Dot 打开电脑视图不等于接管；本机内容默认隔离，用户需选择连接本机
已连接应用 借助 ChatGPT 应用连接器，在邮件、协作、文档等服务中查找和处理工作 可访问哪些内容及能执行哪些操作取决于连接器、用户授权、任务和规则；不能由“4,000+ 应用”直接推导每个应用都支持写入
后台主动研究 用户没有正在对话时，读取已连接应用信息，发现进展、关联和可能需要处理的事项 官方称此研究阶段使用只读工具，不能发送消息、改动应用内容或控制电脑；后续动作须走权限和审批机制
多任务与长任务 Dot 可以并行推进多个项目；用户可继续补充任务、查看进度、提出问题或改变方向 持续运行不等于任务必然成功；OpenAI 明确提示重要结果仍要复核
Activity 工作记录 查看前台与后台任务、进度、结果、等待事项；对运行中的工作补充指示或停止 等待登录、应用连接或审批时需要用户处理；任务记录也承担进度监督入口
Scheduled 定时工作 设置周期性检查、提醒和持续责任，在 Scheduled 中查看、修改或取消 具体定时规则和触发能力以账户当前界面为准；一般 ChatGPT Scheduled 文档不能全部视作 Dots 专属承诺
规则、权限和审批 连接或断开应用；设置特定动作自动执行、明确要求后执行、先审批或交给用户处理 规则不能扩大应用授权，也不能覆盖内置安全要求；改密码等敏感行为必须由用户完成
跨渠道联系 在 ChatGPT 桌面、网页和移动端发消息或语音通话；也可从 Slack、Microsoft Teams 联系同一个 Dot 官方称短信入口“coming soon”；不同渠道会话显示分开，但 Dot 的记忆可跨渠道使用，跨渠道分享仍受权限约束
多模态工作产物 按研发、内容、分析、销售等场景准备代码修复、应用、文档、图表和草稿，供用户检查 官方公告中的案例说明目标体验，不等于每种产物都有固定模板或成功率保证
企业专用 Dot 为专职工作设置独立身份、凭据、系统访问和人工复核流程 当前是聚焦试点；Microsoft Agent 365 集成是合作方向，不应描述为已全面交付

功能口径主要依据 OpenAI 产品公告 及 Dots 入门、任务与记忆、电脑与应用、控制与审批、联系 Dot 官方文档。

四、优势与不足

优势

  1. 上下文连续。 对个人偏好、既有决定和进行中的责任有跨任务记忆，适合需要多次跟进的项目。
  2. 能直接操作工作环境。 自有云电脑与浏览器让它可以处理没有结构化 API 的网页流程；用户也能检查屏幕并在敏感环节接管。
  3. 应用网络和沟通入口较广。 ChatGPT、Slack、Teams 与插件生态组合，有机会把“发现信息—处理任务—汇报结果”放在连续工作流里。
  4. 把主动性和权限控制一起设计。 后台主动研究限定为只读；可能影响账户或对外分享的动作进入自动审查、规则和审批流程；Activity 提供追踪与改向入口。
  5. 个人与企业路径同时布局。 个人 Dot 面向广泛的知识工作，企业专用 Dot 则尝试用专属身份和系统权限承接职责明确的流程。
  6. ChatGPT 分发和模型入口有优势。 现有 ChatGPT 用户可以在熟悉的应用里创建和使用 Dot，首个 Dot 包含在指定计划中，不需要另行部署 Agent 基础设施。

不足与风险

  1. 开放范围有限且分阶段。 首批用户、计划和市场受限；企业功能仍需管理员开启 Beta 或参与试点。
  2. 用量与成本可预期性不足。 公告提到包含一定深度工作额度，也提到发布首月有延长限制，但没有给出通用数字或每类任务消耗模型。复杂用户难以据此估算使用边界。
  3. 执行效果仍需人工复核。 Agent 会在电脑、应用和账户中采取行动；错误可能造成真实影响。OpenAI 也明确提醒重要工作需要复核。
  4. 连接能力不等同于完整自动化。 不同插件支持的读取、写入、审批和稳定性会不同；未接入或流程不支持 API 的站点仍可能依赖视觉操作或用户接管。
  5. “常驻”和主动研究要求较高的信任。 用户需要理解 Dot 读取哪些已连接信息、保存哪些笔记、在什么情况下主动通知，以及跨 Slack/Teams 分享信息的边界。
  6. 个人版与组织版治理复杂度不同。 个人 ChatGPT 计划的数据使用设置与 Business、Enterprise、Edu 的默认训练策略不同；企业还需要明确身份、授权、审计和数据保留策略。
  7. 多 Agent 组织化仍在演进。 当前个人产品以一个主要 Dot 为起点；组织专用 Dot 和多个 Dot 协作还没有成为普遍可用的成熟产品能力。

六、各产品的竞争位置

OpenAI Dots

适合关注： 已经在 ChatGPT 里工作、需要跨应用处理知识工作，并希望后台任务有明确进度和审批入口的个人或团队。
竞争长处： ChatGPT 的模型与上下文、应用连接生态、工作场景覆盖，以及把主动研究限定为只读并提供审查控制。
竞争压力： 竞争对手把“个人代理”做得更具体：Muse 深入消费者生活与 Meta 生态；Cue 把电话、邮箱、钱包设计成 Agent 自有身份；Grok Bot 已把多 Bot 分工和示范学习作为产品核心。Dots 的长期领先取决于这些能力能否从公告与试点变成可靠、可预期的日常工作。

Meta Muse

Muse 的长处是用户熟悉的沟通方式、Meta 内容与社交入口，以及家庭、出行、购物等个人任务。Meta 官方主张每人拥有隔离 VM，并由独立 Sentinel 检查互联网访问；它也强调密码不可见、敏感操作确认、完整操作轨迹。产品优势与隐私疑虑同时来自同一个事实：助理越了解用户的生活和账户，越需要用户相信它的数据隔离、模型训练和外部访问规则。

Manus Cue

Cue 把 Agent 的身份和执行渠道做得最具象：它可以拥有自己的电话、邮箱、电脑和钱包，还可创建多个专职 Agent，在群聊中协作。若兑现，这使它适合跨电话、邮件、预订与付款的完整事务。风险是对权限边界、支付控制、错误纠正和审计提出更高要求；公开页面没有提供足够的统一价格、地区覆盖、成功率或可审计安全细节，需以实际开放体验继续验证。

Grok Bot

Grok Bot 更像可协作的数字队伍：多个 Bot 并行、互相交接任务，能把演示过的流程存为 Skill 并按计划运行；每个 Bot 还有自己的对话记忆和屏幕。其关键权衡是同一账户下 Bots 共用云电脑、浏览器登录、文件和命令行凭据。这样便于共享状态和交接，但官方明确说明这不是安全隔离边界，适合由同一用户统一管理的一组 Bots，不适合将 Bot 之间视作互不信任的租户。

七、综合判断

  1. Dots 站在 ChatGPT 生态的延长线上。 它尝试把聊天、记忆、应用、网页操作、定时任务和审批融合到一位持续协作的 Agent 身上。
  2. Muse 争夺“个人生活入口”。 Meta 的应用与设备触达、基础免费策略和个人数据建模，可能降低新用户启用门槛。
  3. Cue 争夺“代办事务的执行权”。 自有电话、邮箱与支付身份让 Agent 更接近代理人，而非只在用户账户里写草稿的助手。
  4. Grok Bot 争夺“可扩展的数字同事团队”。 它以多 Bot 编排和可复用 Skill 提升重复工作能力，同时接受账户内共享电脑带来的隔离限制。
  5. 市场胜负取决于任务闭环。 应比较用户给出同一个长期任务后，各产品能否持续、准确、可审计地完成；应记录所需纠正次数、成功完成率、人工审批次数、失败后的恢复能力和每月可用工作量，而不是仅凭发布视频或模型名称排名。

八、仍需跟进的问题

  • Dots 各市场的具体开放清单、Business Premium 的计划定义及 Enterprise/Edu/Healthcare Beta 的申请条件。
  • Dots 深度任务配额、任务时长、并发数和超额后的行为。
  • 4,000 多个连接器中，关键应用各自支持的读写范围、触发方式、速率限制和企业管理能力。
  • 后台主动研究的运行频率、可见的来源范围、通知控制和保存周期。
  • 个人 Dot 多任务的优先级策略，以及多 Dot 协作的正式发布日期。
  • Muse 的完整订阅档位和开放地区；官方“多数需求免费”的具体额度与上限。
  • Cue 的公开定价、地区可用性、钱包资金保护与争议处理、Agent 电话和邮箱的账号归属规则。
  • Grok Bot 的各订阅层级配额、企业管理能力，以及共享云电脑下敏感凭据的最佳隔离做法。
