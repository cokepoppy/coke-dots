## Coke Dots behavior implemented

- The public videos show a phone-shaped call surface in V1 and a compact microphone/hang-up state in a desktop conversation in V2. V2 does not provide a clear enough frame to measure a floating card. Following the requested desktop/web interaction, Coke Dots uses one small floating card at all browser widths; its exact size and right-side placement are an implementation choice, not a measured pixel replica. The phone-frame CSS and mobile-layout assertions have been removed from the web call.
- The card shows the Dot avatar and name, connection/listening/working state, elapsed time, the latest voice transcript/task state, neutral microphone and speaker toggles, and one red hang-up action. There is no answer button because the web call starts as an outgoing call. After the selected voice transport is ready, the Dot greets the user in Chinese; browser speech recognition starts after the greeting audio ends.
- Each recognized turn still becomes a tenant-scoped task and appears in the conversation timeline. The card remains open during multiple turns. The task response is spoken back through the selected voice provider, and hanging up ends the call while already assigned work continues.
- With the browser provider, Chrome's SpeechRecognition/webkitSpeechRecognition converts each final utterance into a normal task in the selected tenant. Qwen and Volcano adapters can instead stream microphone audio over WebRTC or a server-mediated WebSocket and return provider-generated transcript/audio events. The text composer stays available during the call. The current Coke Dots Demo runtime selects `volcengine`; its server-side API-key configuration resolves to **Doubao SeedDuplex 3.0**. Qwen remains an optional adapter with regression coverage and is not the selected runtime route.
- When the task being followed reaches `waiting`, its ID is retained for the next final utterance. That utterance uses the existing tenant-scoped task-reply endpoint, resumes the same task with the original goal, and keeps the task ID. If the reply request fails, the waiting task ID is restored so the next utterance can retry it.
- While the call is open, the UI follows task state. Browser speech synthesis reads results on the browser provider; Qwen and SeedDuplex speak acknowledgements and Agent updates through their realtime sessions. Provider audio can be interrupted by a new speech turn.
- Hanging up ends the persisted call session and stops call UI polling/speech; the independent background task continues in the server worker.
- The global Dot conversation merges persisted call-end events with its chat timeline in chronological order. After reload, an ended call appears as the observed purple “Me: Call ended” chip with the smaller “Optional” label; another tenant does not see that call history.
- SQLite stores call owner, workspace, start/end time, and elapsed duration. It stores no audio or raw call transcript. The recognized request is retained through the normal task instruction and activity records.
- The browser provider still depends on browser speech support. A browser without recognition reports that typing is available, and microphone denial leaves the text composer usable. Qwen/Volcano provider paths require microphone permission and a configured server-side credential.
