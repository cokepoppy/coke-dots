# Slack contact setup evidence

## Product evidence

- Official Dots documentation says the same Dot is reachable across connected contact methods, and users connect those methods from the Dot profile. It identifies Slack direct messages and channel mentions in threads as supported ways to contact the Dot. By default, the Dot replies to the user; sharing context from a private conversation with other people needs permission. Adding a Dot to a channel does not itself configure monitoring. Source: [Message your dot](https://learn.chatgpt.com/docs/dots/channels).
- In V2, the right side panel at 07:11–07:12 shows the active Dot, Call and Slack actions, its connected computer, Recent activity, and Outputs. A Chrome replay at 07:14 shows a “Set up Slack” modal. A second sample at 07:21 shows the same modal. The visible controls are a “Your dot in” workspace picker with ASPI displayed, “Select another,” the helper “Choose the workspace to add Roger to Slack,” a “Select a workspace” button, and a close control.
- The 07:14 and 07:21 states were directly viewed in the user's Chrome session. Separate PNGs were not retained. These are timestamp samples, not continuous frame-by-frame inspection. The trigger click, Slack OAuth consent, completed installation, and any inbound or outbound Slack message are not visible. Do not infer those steps from this modal.
- The installed Slack desktop app was opened read-only to verify the available local client and its current workspace. Its channel and huddle UI is Slack itself, not evidence for Dots' Slack setup flow; no Slack message was sent or changed.

## Implementation boundary

Coke Dots reproduces the observed compact workspace-selection state: “Your dot in,” the selected workspace, “Select another,” the helper text, and the “Select a workspace” action. Opening “Select another” reveals the workspace list. Proactive monitoring controls remain available under “More Slack settings” so they do not change the initial state seen in the video. This disclosure remains open across a modal refresh. The measurements are based on sampled compressed video frames, not a source screenshot with known CSS pixels.

The modal implements a Slack OAuth v2 workspace installation flow requesting `chat:write`, `app_mentions:read`, `im:history`, `im:write`, `channels:read`, and `channels:history`. The public-channel scopes support the opt-in monitor described in [proactive Slack monitoring](slack-proactive-monitoring.md); existing Slack installations must reauthorize to receive these added scopes. OAuth state is one-use, ten-minute, and bound to the signed-in user and active tenant. Bot tokens are stored in macOS Keychain under a tenant-and-Slack-team-derived account name; SQLite stores only installation metadata and granted scopes. Selecting a contact workspace is tenant-scoped, and only workspace owners or admins can connect or change it. The Slack identity that completes OAuth is linked to that Coke Dots member. A member can inspect the current shared selection.

The message bridge accepts `message.im` and `app_mention` events at `/slack/events`. It verifies Slack's HMAC signature against the raw body, rejects timestamps more than five minutes old, and deduplicates by Slack `event_id`. The handler stores an event and tenant-scoped task before returning; the background worker then runs the task and posts its final, waiting, or failed result through `chat.postMessage`. Direct messages reply to their existing DM channel. A channel mention opens a private 1:1 app DM using `conversations.open` (`im:write`) before posting, so it does not publish the result in the source channel. Delivery retries are bounded, honor Slack's `Retry-After` response, and become visible as dead-letter rows after five attempts. Direct messages and mentions are accepted only for the Slack identity linked during OAuth. If the same Slack sender resolves to more than one selected Coke Dots tenant, the event is ignored rather than dispatched ambiguously.

The server needs `SLACK_SIGNING_SECRET`, and the Slack app's Events API must point to the publicly reachable `/slack/events` URL with the `app_mention` and `message.im` bot events subscribed. Reauthorize existing installations to grant the added scopes. The `/api/slack` status shows whether the signing secret is configured; it cannot confirm that the Slack developer console has the correct request URL and subscriptions. Slack documents `chat:write` for sending messages, `im:write` for opening a 1:1 DM, and app mention/DM event subscriptions; the request verification guide defines the signed raw-body validation used here. See [Slack OAuth v2](https://docs.slack.dev/authentication/installing-with-oauth/), [Slack request verification](https://docs.slack.dev/authentication/verifying-requests-from-slack/), [`conversations.open`](https://docs.slack.dev/reference/methods/conversations.open/), [`chat.postMessage`](https://docs.slack.dev/reference/methods/chat.postMessage/), [app_mention event](https://docs.slack.dev/reference/events/app_mention/), and [message.im event](https://docs.slack.dev/reference/events/message.im/).

## Verification

The Chrome UI E2E uses a local-only mock Slack provider. It clicks through OAuth and workspace selection, asserts that the sampled compact state is visible before opening the workspace list, and checks that the advanced controls start collapsed. The same 57-step browser run sends signed DM and channel-mention events, waits for the task worker, verifies the result, and confirms that DM replies return to their source conversation while channel mentions receive a private app DM. It also tests proactive monitor setup, event review and deduplication, pause/resume, tenant isolation, and shared-workspace permissions. Unit tests cover HMAC validation (including stale timestamps and altered bodies), tenant identity mapping, duplicate delivery, ambiguous sender rejection, and queueing results. Tests use local fixtures; they do not exercise a live Slack app, hosted consent page, or Slack-delivered event. The video evidence remains limited to the workspace picker; it does not show OAuth completion or message exchange.
