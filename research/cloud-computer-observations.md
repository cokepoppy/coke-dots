- The Linux desktop had been starting at `example.com`, unlike the directly observed welcome screen. It now starts at `about:blank`; the restricted desktop Worker supplies the shared welcome page before the first screenshot and applies the tenant's Dot name when Coke Dots opens that computer.
- The shared page keeps the observed copy, light doodle wallpaper, avatar, clock, shortcut grid, and fixed arrangement across local Chrome and Debian Chromium. The first two shortcut rows use small inline SVG drawings based on the visible app marks. This is a reference-backed first screen, not evidence about Dots' underlying operating-system image.
- The observed welcome note, page background, note width, browser colors, mascot, and launcher-row baseline were compared against the 04:44 frame. For the current 1440×1080 screenshot, the comparison covers 1,555,200 pixels and reports mean absolute channel error 6.95/255 and 7.34% of pixels above the 32-channel threshold. That is a measurable improvement over the 12.09/255 initial layout baseline, but it is not pixel parity. Remaining differences include the source avatar texture and small icon details, video compression, font rasterization, and Chromium's platform-specific chrome.
- The Coke Dots computer view keeps the agent/user owner status and hand-back action centered below the remote desktop. During takeover, the authenticated viewer hides the noVNC example toolbar so the desktop fills the 4:3 canvas, then outlines the live canvas in the observed orange. Chrome E2E covers takeover, navigation, clicking, typing, and return. K3D E2E checks the rendered orange border pixels in a real Debian session.

## Remaining visual limits

The video does not provide a clean desktop-only source frame, native screen resolution, exact browser zoom, or original UI assets. Small labels and icon artwork are blurred by the video scale. We can compare relative arrangement and visible state, but we cannot honestly claim pixel parity from this footage alone. Preserve each measured frame, fixed viewport, and comparison output as the target is tuned; keep unshown transitions marked unverified.
