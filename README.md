# Coke Dots

An evidence-led, local-first personal agent project. Features are developed on separate branches, with observed Dots behavior recorded before implementation.

## Run locally

Requires Node.js 24 or newer. Copy `.env.example` to a local environment file (do not commit OAuth credentials), register a Google OAuth web client, and set `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and the exact callback URI `http://127.0.0.1:4317/auth/google/callback`. Then run `npm install` and `npm run dev`, and open `http://127.0.0.1:5173`. Google sign-in requests only OpenID Connect identity, email, and profile scopes.

The model API is configured from a workspace's dot profile. Its API key is stored under that workspace's account in macOS Keychain; model endpoint and name are stored in tenant-scoped SQLite settings. The optional `DOTS_MODEL*` environment settings are retained only for the original local bootstrap workspace.

The background worker and web UI are separate processes. Closing the browser window leaves the worker running. `DOTS_DATA_DIR` defaults to `./data`; the SQLite database is never committed. Starting the server again recovers any task left in `working` state. Without a configured model, tasks explicitly fail and can be retried after configuration.

For the Mac shell, run `npm run desktop`. It builds the web UI, server and Electron wrapper, starts a detached local server if needed, and opens the app. Closing the window leaves that server running. `npm run dev:desktop` runs the UI with Vite. The current shell requires Node.js 24 on the Mac and is a local development build, not a signed installer.

## Automated browser tests

Run `npm test` for the unit suite and `npm run test:e2e` for the Chrome click-through. The unit command and browser fixture use isolated Keychain service names so developer workspace credentials are not read as test data. The browser suite builds the web client, launches a loopback-only service against a fresh temporary SQLite directory, and records viewport screenshots, browser video, Playwright traces, server logs and a JSON manifest under `artifacts/e2e/<run>/`. It needs local Google Chrome; set `DOTS_CHROME_BIN` if Chrome is installed elsewhere.

The suite covers login-screen rendering, Google OAuth through Chrome, the account popover and its workspace/theme/logout controls, three-account isolation, pending workspace invitations and acceptance/revocation, member removal, role controls, persistent tasks and redirection, the paged tenant-scoped Activity log and task navigation, explicit task stop while a model request is running, cancellation of a pending page approval when its task is stopped, explicitly managed workspace memories reaching the model request, tenant-scoped custom rules for Scratchpad writes, pending approval with member review, approve/decline without premature writes, agent-created Scratchpad pages opened from chat, recurring schedules, service-restart recovery, tenant-scoped availability and credentials for the Model API, Pi, and DeepSeek Harness kernels, the computer browser's open/take-over/navigate/click/type/return path, Model API research through the tenant computer, and personal Dot reset cancellation/confirmation, tenant-scoped cleanup, and first-run recovery. Alpha follows the rendered Google authorization redirect and checks state-cookie protection, state mismatch rejection, PKCE S256, authorization-code exchange, issuer/audience/nonce/signature verification by `google-auth-library`, verified-email gating, and stable user/workspace recovery after logout. The Google endpoints are provided by an ephemeral loopback OIDC server with test-only credentials; injection is restricted to `NODE_ENV=test`, `DOTS_E2E_AUTH=1`, and a loopback URL. This exercises the production OAuth library and callback handler without transmitting credentials to Google, but it does not exercise Google's hosted consent screen or a registered client. Beta and Gamma use a fixture accepting only `@example.test` identities in the disposable test database. Local screenshots and recordings document Coke Dots behavior; reference-frame overlays and pixel-difference reports are tracked in the [evidence ledger](research/README.md), and compressed YouTube frames do not establish absolute pixel parity.

The private Dot-memory click-through also confirms that a personal task saves a note, the same account can see and edit it in Profile, the next task receives it, and neither a shared-workspace prompt nor a second account receives it. See [the evidence limits and implementation policy](research/personal-dot-memory.md).

Personal Dot reset follows the official deletion warning and fresh-Dot landing behavior. It is restricted to the sole owner of a personal workspace, clears that Dot’s local activity and runtime data, and preserves account sign-in and provider setup. The public videos do not show the reset dialog, and live K3D namespace deletion is not yet covered by the browser test. See [reset evidence and boundaries](research/personal-dot-reset.md).

Current agent execution includes one-level delegation to up to three independent child tasks. Each child uses an explicitly selected engine only when that engine is available in the tenant's current runtime set; omitted choices inherit the parent's engine. Children cannot delegate recursively and return their outcomes to the parent. Activity cards identify each child's engine. Tenant scope and the existing task-level engine choices are preserved.

Agent execution also includes a tenant-scoped Scratchpad page action when enabled by the active workspace rule. The first custom-rule scope offers the four documented handling modes for Scratchpad writes; an approval-mode proposal is persisted without changing the page until a workspace member approves it. The Model API, Pi, and DeepSeek Harness share the same read-only public-page browser tool; it cannot sign in, click, enter forms, download files, or write to a site. DeepSeek Harness receives it through a per-run Cordis patch and a random-token loopback bridge. Its Dots profile disables shell, filesystem mutation, web, delegation, and workflow tools for this adapter run. External-account tools remain separate feature work, and Scratchpad rules do not grant them. The agent must not claim it performed external actions when no tool was used. See the [browser research boundary](research/model-browser-research.md) and [evidence ledger](research/README.md) for confirmed behavior and visual gaps.

Activity can stop an individual one-off task, including a delegated child. Stop is terminal, interrupts supported active agent calls, and cancels that task's pending local page approval without writing the proposed page. Stopped tasks cannot be resumed or redirected. Stopping a parent stops its active children; stopping one child leaves its parent waiting for the remaining children.

Scheduled also supports explicit HTTPS page monitors. The first successful check saves a text baseline; later content changes create a tenant-scoped read-only review task and a desktop notification when enabled. Page text is passed to the agent as untrusted source data. These reviews cannot write Scratchpad pages, delegate, schedule follow-up runs, modify files or accounts, or send messages. The Scheduled detail links to the latest review. Current extraction removes scripts, styles, comments and document metadata before comparing snapshots; this does not claim to reproduce a site's fully rendered visual state.

## Agent engines

The host-runtime tenant boundary and its tests are recorded in [the tenant engine isolation evidence](research/tenant-engine-isolation.md).

Each task records its selected engine and its own workspace. The adapter contract returns a durable state (`done`, `waiting`, `scheduled`, or `delegating`), message, optional next check time, optional native session ID, up to three bounded child instructions, and an optional `notifyUser` choice. Routine completion and informational delegation can be quiet when a task's update criteria say no notification is needed; a required user reply, approval, hand-off, or failure remains visible. A child can choose one of the engines currently available to its tenant, or inherit its parent's engine. The UI shows available engines and keeps each task's choice on retries and restarts.

If the Model API adapter is unavailable, the task fails before making a model request and its Activity entry names the missing tenant-scoped API key and/or model name.

- **Model API:** OpenAI-compatible Chat Completions via profile settings or environment variables. The profile saves only model name and endpoint in SQLite; the API key goes to macOS Keychain. The adapter can use one bounded, read-only public-page tool in the tenant's Dot computer. It screens public HTTPS addresses, pins DNS, revalidates redirects, rejects existing site sessions, and returns a sanitized text snapshot. It cannot sign in, click, type, download, or write to a site; web content is treated as untrusted evidence. See [the research feature boundary](research/model-browser-research.md).
- **Pi:** Install the optional `@mariozechner/pi-coding-agent` package and set `DOTS_PI_ENABLED=1`. For a Google-authenticated workspace, the adapter registers that workspace's Model API endpoint and model with an in-memory Pi credential store; it never reads the host `~/.pi/agent/auth.json`. The Pi agent directory is mode `0700` under `data/tenants/<tenant>/agent-runtime/pi`, while native conversation history stays in the task workspace at `.coke-dots/pi-sessions`. Retries and scheduled runs reopen the task's stored session ID; missing, ambiguous, or cross-workspace session IDs fail closed. The local bootstrap workspace can still use a configured host Pi profile when no Model API is set. See [the session persistence evidence and checks](research/pi-session-persistence.md).
- **DeepSeek Harness:** Install the optional SDK and DSH CLI, set `DOTS_DSH_BIN` and an explicit `DOTS_DSH_PROFILE` (normally `sdk`), then configure any approved profile overlay in `DOTS_DSH_READ_ONLY_CONFIG`. Google-authenticated workspaces need their own Model API credential; the adapter passes only that key, endpoint, and model to the child process, sets an explicit mode-`0700` `DSH_HOME` under `data/tenants/<tenant>/agent-runtime/dsh`, and removes unrelated host API credentials from the child environment. Each run injects a temporary Cordis tool patch and disables shell, filesystem, web, delegation, and workflow tools for this adapter task. The browser bridge binds only to `127.0.0.1`, uses a per-run random token, and is removed when the run ends. The SDK returns a native session ID. When a task resumes in a newly started DSH process and the runtime rejects that saved ID as already present, Coke Dots retries once with a fresh ID; the same task prompt includes its prior result and completed child results. This preserves task progress but does not restore the full hidden native transcript. See [the observed DSH recovery path](research/dsh-session-recovery.md). The local bootstrap workspace can still use its host Harness profile when no Model API is set.

All engines must return the same structured task decision. A missing engine, invalid output or failed call is surfaced as a failed task; Coke Dots does not fabricate success. External write and send permissions are not yet connected to these engines.

### Live model smoke check

`npm run test:live-model -- --keychain` exercises the same adapter used by background tasks with the `legacy` workspace's saved endpoint, model, and Keychain key. It makes one small real request, verifies the structured task response and a unique marker, and prints status and timing without printing the response or key. `npm run test:live-model` can also take `DOTS_LIVE_MODEL_API_KEY`, or `--stdin-key` reads it without terminal echo; those modes do not store the key. Defaults are base URL `https://api.deepseek.com` and model `deepseek-flash`, from the [DeepSeek Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/).

`npm run test:e2e:live-model` is an opt-in Chrome click-through that signs into a disposable local workspace, submits one real background task using the saved Keychain credential, and checks the completed result in Activity. It uses a temporary SQLite database, writes no test task to the real workspace, and records only status, model, marker presence, and a screenshot. The default `model` run sends one request. Set `DOTS_LIVE_MODEL_ENGINE=pi` or `DOTS_LIVE_MODEL_ENGINE=dsh` to test an alternate kernel; those runs first send one short Model API task to open the conversation and expose the kernel picker, then send one task through the selected kernel. DSH mode also needs `DOTS_LIVE_DSH_BIN` or an executable `dsh` on `PATH`; set `DOTS_LIVE_DSH_PROFILE` to override the `sdk` profile.

`npm run test:e2e:live-dsh-delegation` is a more involved opt-in real-API Chrome test. It asks DSH to run one DSH child task, then verifies that the parent recovers from the SDK's persisted-session collision, synthesizes the child result, and shows the final result in Activity. It uses disposable SQLite state and the saved Keychain credential; the full local recovery evidence and limitation are documented in [the DSH session recovery record](research/dsh-session-recovery.md).

## Accounts and tenant isolation

Google's immutable OpenID Connect `sub` identifies a user; verified email addresses are used to address workspace invitations. The first Google account claims the pre-authentication local workspace, preserving any existing local data. Later accounts get separate personal workspaces. Users can create additional workspaces and switch among memberships. An owner or admin can invite a verified Google email; the matching account must sign in and explicitly accept within seven days before it becomes a member. Pending invitations can be revoked, and removing a member revokes that member's sessions in the workspace. Coke Dots does not send invitation email; the inviter must notify recipients separately.

Every task, activity entry, scheduled check, profile, model setting, workspace directory, and computer browser profile is scoped by tenant ID. API requests require an opaque server-side session in an HttpOnly cookie and the session's selected workspace membership is checked on every request. Google ID tokens are signature/audience/expiry verified; OAuth state, PKCE, and nonce are validated. The server binds to loopback. The optional Mac demo exposes only a dedicated HTTPS path through the VPS and an SSH reverse forward; its OAuth client, tenant database and proxy token are separate from local development. See [the VPS demo setup](deploy/vps-demo/README.md). A workspace's owner/admin manages its shared Model API credential. Local Pi and DeepSeek Harness adapters require that explicit workspace credential for Google-authenticated tenants and use separate tenant-scoped runtime directories; they do not inherit the Mac host's CLI identities. Shared workspace members use the workspace credential and runtime; per-member credentials within a shared workspace are not implemented.

Each workspace can keep up to 20 shared notes (up to 1,000 characters each). Members can read them; creators and workspace administrators can edit or delete them. Separately, a Google account can keep up to 20 private Dot notes in Profile. In a single-owner personal workspace, the agent may propose at most three note changes from the signed-in user's direct messages; it does not derive notes from attachments, quoted text, web pages, or tool results, and it rejects credentials and sensitive categories. Personal notes are included only in that account's personal-workspace tasks, never in a shared workspace. Users can inspect, edit, or delete them. The private-note interface and update policy are Coke Dots implementation choices because the reviewed Dots videos do not show this UI; see [the evidence and limits](research/personal-dot-memory.md).

The local server supports the Pi and DeepSeek Harness CLI runtimes. Their host-account credentials are visible only to the local bootstrap workspace; model API credentials remain tenant-scoped. Claude Code is not currently supported. Shared workspace members use the workspace's configured runtime.
