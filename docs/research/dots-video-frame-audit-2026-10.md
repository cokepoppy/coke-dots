## 主题与画面记录

- Futurepedia 主流程录屏展示的是深色主题：近黑色画布、深灰消息块、较窄的图标栏、左侧会话列表。当前这段视频没有展示浅色主题的切换操作。
- Coke Dots 首次进入采用浅色，右上角主题按钮可切换深色，并按当前用户保存选择。浅色下侧栏为浅灰，内容区为白色；深色下为近黑色。`color-scheme` 也显式跟随当前主题，避免浏览器原生表单控件因 macOS 系统外观而反向显示。
- 视频含 Futurepedia 水印、创作者摄像头、剪辑、播放器叠层和缩放后的桌面画面。原始窗口 CSS 像素、字体栅格、滚动位置和鼠标点击坐标不可从压缩画面精确恢复；导出原始参考裁剪并锁定视口、缩放和字体前，不声明像素级一致。
- 早先的系统按键序列确实产生 31 张逐像素相同的屏幕图（0/628,320 像素不同）；后来改从 Chrome DevTools 读取播放器、按 30 fps 设置下一帧时间并核对 `seeked` 时间，完成了上面 48 张手机/桌面样本。证据目录包含截图序列；本记录只把这些时间区间称为逐帧取样，未把它扩大成全片逐帧审阅。
- 两段语音录屏展示不同呈现方式：Futurepedia 06:48 是创作者旁的手机演示；John Aspinall 06:32–07:42 是桌面聊天和通话控制。实现和视觉比对时分别处理两种布局，不合并其尺寸或状态。
- 因此，布局复刻按归一化比例和可读控件状态核对；对清晰、未遮挡的局部截图再做叠加/差异比较。不能用此视频单独证明整页达到像素相同，也不能补写未出现的流程。

## 已执行的本地对照

- Web 端 E2E 把系统外观设为深色，再通过可见控件在浅色、深色间切换；这能证明首次打开仍为浅色，并分别检查主题属性、侧栏和主区背景色。
- 本轮新增检查浏览器实际计算出的 `color-scheme`：浅色为 `light`，深色为 `dark`，覆盖系统表单控件和滚动条的外观选择。
- 头像编辑器仍以 John Aspinall 视频 02:46 的局部截图做叠加比较；比较指标和源裁剪保存在 `artifacts/reference-comparison/avatar-editor-v2-0246/`。视频水印与压缩仍会影响像素差值。
- Futurepedia 06:50 手机通话屏的原图裁剪保存在 `artifacts/reference-comparison/futurepedia-mobile-call-0650/reference-crop.png`（560×1122）；同一片段另有 12 帧 Chrome 序列，播放器裁剪为 1800×1030。两者都是独立手机布局证据，没有拿手机屏幕比例缩放桌面通话控件。
- 桌面通话 E2E 检查控制条是否逐像素对齐 Dot 资料栏顶边/左右边；挂断后按 `4m 46s · Call ended` 的已见文案格式生成靠右紫色气泡和 `Delivered` 状态。对应本地 Chrome 截图位于 `artifacts/e2e/<run>/screenshots/voice-call-active-light.png`、`voice-call-active-dark.png` 与 `voice-call-ended-work-running.png`。
- Chrome E2E 模拟麦克风返回 `not-allowed`，确认活动控制退出、资料栏显示中文权限提示，再次授权入口可重新发起通话。失败状态截图位于 `artifacts/e2e/2026-10-06T07-38-09-442Z/screenshots/voice-call-microphone-denied.png`；此用例验证 UI/恢复逻辑，不代表真实麦克风权限已在本机授权。
- 每次 E2E 的逐步截图、trace 和执行清单由 `npm run test:e2e` 写入 `artifacts/e2e/<run>/`，可复核交互和失败截图。

## 后续证据缺口

待继续采集并落盘的状态包括：Dot 创建完成、改名、逐项头像编辑、加入/取消建议、Activity 展开、任务被打断后恢复、审批拒绝、定时任务暂停/恢复、电脑查看与接管/交还。语音仍待验证真实设备麦克风授权、识别服务不可用、通话中切换工作区等路径；浏览器自动化目前通过模拟识别/合成事件验证逻辑，尚未用真实麦克风和语音服务验收。公开视频里的手机是经过合成和缩放的画面，仍缺原始产品视口与字体环境，无法据此做可信的像素差异。公开视频已显示的任务详情错误、云电脑启动故障和素材库上传受阻也需要在本地 E2E 中设计可核对的错误状态；视频没有清楚呈现的细节继续标注为待验证，等有直接实测或官方文字流程支持后再实现。
