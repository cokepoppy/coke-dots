## 主题与画面记录

- Futurepedia 主流程录屏展示的是深色主题：近黑色画布、深灰消息块、较窄的图标栏、左侧会话列表。当前这段视频没有展示浅色主题的切换操作。
- Coke Dots 首次进入采用浅色，右上角主题按钮可切换深色，并按当前用户保存选择。浅色下侧栏为浅灰，内容区为白色；深色下为近黑色。`color-scheme` 也显式跟随当前主题，避免浏览器原生表单控件因 macOS 系统外观而反向显示。
- 视频含 Futurepedia 水印、创作者摄像头、剪辑、播放器叠层和缩放后的桌面画面。原始窗口 CSS 像素、字体栅格、滚动位置和鼠标点击坐标不可从压缩画面精确恢复。
- 本次用 Chrome 在选定的界面片段按 5 秒步长暂停并检查画面；这不是对视频每个编码帧的穷举，也不是原始产品的连续操作录屏。表格只记录能在取样画面中辨认的内容，并明确记下 presenter-only 片段和产品报错。
- 因此，布局复刻按归一化比例和可读控件状态核对；对清晰、未遮挡的局部截图再做叠加/差异比较。不能用此视频单独证明整页达到像素相同，也不能补写未出现的流程。

## 已执行的本地对照

- Web 端 E2E 把系统外观设为深色，再通过可见控件在浅色、深色间切换；这能证明首次打开仍为浅色，并分别检查主题属性、侧栏和主区背景色。
- 本轮新增检查浏览器实际计算出的 `color-scheme`：浅色为 `light`，深色为 `dark`，覆盖系统表单控件和滚动条的外观选择。
- 头像编辑器仍以 John Aspinall 视频 02:46 的局部截图做叠加比较；比较指标和源裁剪保存在 `artifacts/reference-comparison/avatar-editor-v2-0246/`。视频水印与压缩仍会影响像素差值。
- 每次 E2E 的逐步截图、trace 和执行清单由 `npm run test:e2e` 写入 `artifacts/e2e/<run>/`，可复核交互和失败截图。

## 后续证据缺口

待继续采集并落盘的状态包括：Dot 创建完成、改名、逐项头像编辑、加入/取消建议、Activity 展开、任务被打断后恢复、审批拒绝、定时任务暂停/恢复、电脑查看与接管/交还。公开视频已显示的任务详情错误、云电脑启动故障和素材库上传受阻也需要在本地 E2E 中设计可核对的错误状态；视频没有清楚呈现的细节继续标注为待验证，等有直接实测或官方文字流程支持后再实现。
