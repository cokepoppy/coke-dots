## 演示目标

让观众看到同一条个人助理流程：手机拨打 Dot → 用中文读取现有日程、用户指定复用的会后语音速记和待办 → 用户授权落实评审要点 → Pi 在租户 Debian 云电脑里检查代码、修复、测试、打开页面 → 用户验收 → 创建未合并 PR。用户自行在手机上测试通话；不要求把手机连接到 Mac。整个场景不连接券商、不提交交易委托、不合并或部署代码。

## 推荐会议室布置

1. 用户用手机 Chrome 打开公网 `https://codex.cokeagent.com/dots-demo/`，用 Google 主账号登录并用手机麦克风/扬声器自行测试 Dot Call；无需连接 Mac 或提供设备调试通道。
2. 投影显示同一账号下的 Dots 公网页面与 Dot’s computer 浏览器画面，让观众看见 Activity 和云电脑动作。只有已在同一用户流程验证的同步状态才做演示；不假设手机通话与投影任务自动联动。
3. 手机与投影电脑都只访问公网域名；公网流量经 VPS 隧道转发到 Mac。Dots、DWS、K3D、Pi 和租户 Debian 云电脑都留在 Mac/Mac-local K3D。

### 语音与等待表现

- 每个电话轮次使用自然的一句话，不在同一电话里重复转述同一请求。当前语音界面把完整转写提交为 Dots 任务；SeedDuplex 的语音角色只做一句简短确认，Dot Agent 的任务结果在完成后再通过语音播报。
- 代码任务执行期间，Activity/任务状态可显示真实阶段进度；当前实现不保证每 30–45 秒由 Dot 语音播报进度。不要用反复口述来制造持续工作的印象。
- 如果任务仍在运行，让投影继续展示真实 Activity；不要在电话里重复提交同一请求。若现场超过预留时间，可结束电话并让后台任务继续，随后从 Dots 任务页查看结果；不能伪称已修复或已建 PR。
- PR 写入必须在用户对页面和测试验收后进行；不合并、不部署。
