## 演示目标

领导能看到并听到一条真实、连续的工作流：手机 Chrome 呼叫 Dot；Dot 查找已结束的北交所规则评审、真实 AI 听记和关联待办；用户明确派工后，Pi 在 Dot 的 Debian 云电脑里检查最新仓库、从最新 `main` 建分支、按会议结论改证券页面、运行测试、在云 Chromium 展示结果，并在用户看过页面后创建一个未合并的 PR。

交易页仓库当前为 `cokepoppy/coke-agent-test-stock-app`。截至本次脚本编写，远端 `main` 是 `adcbde2958d419e1b3cea95b401bde1b727e1c50`，已包含北交所大宗交易页面与规则校验（PR #1、#2 已并入）。因此，**不能把已有实现再包装成新的代码修改或 PR**。真实会议若没有提出新的、尚未合入 `main` 的要求，本次应演示“查找、解释、页面只读核验”，不应制造空改动。若会议提出新要求，实施分支必须从运行时重新 fetch 后的最新 `origin/main` 创建。

应用 README 已说明证券、行情和账户是合成测试数据，订单表单只做本地校验，不连接券商或提交真实委托。产品画面可保持应用自身样式，演示者不得把合成数据说成真实客户账户或实时行情。

## 电话脚本

### 1. 让 Dot 找到真实会议记录

用户说：

> 请查找我 10 月 19 日的北交所交易规则变更评审，读取这次会议实际生成的 AI 听记和关联待办。先用几句话总结结论、待办负责人和截止时间，暂时不要修改文件。

Dot 必须从钉钉实时读取并引用实际找到的会议、听记和待办。回答应报出记录名称/日期与可核验的结论和任务；如果会议未结束、AI 听记未生成或待办关联不到，要如实说明并停在只读状态。禁止把会前资料当成会议听记，也不重建或修改现有日程、听记、待办。

### 会前彩排脚本（仅在会议尚未召开时）

用户说：

> 查一下北交所交易规则变更评审的安排、我已有的相关听记和待办。请区分会前准备和会议结论，告诉我目前确定的事项与截止时间。

截至 2026-10-18 的核验结果应是：日程为 10 月 19 日 10:00–10:45，状态 `confirmed`；唯一相关 AI 听记是《北交所交易规则变更评审会前语音速记》，不是会后纪要；两条当前未完成且指派给用户的待办分别是“复核北交所规则变更对交易终端的影响”（10 月 20 日 17:00）和“验证规则生效日期和移动交易页提示”（10 月 21 日 17:00）。彩排只读，必须明确会议仍未召开，不得接着派发代码修改。

### 2. 明确派发实现工作

用户说：

> 根据这份真实会议听记和关联待办，检查 Coke Agent 证券移动交易页的最新 `main`。只实现会议中确认、而且目前尚未实现的要求；从最新 `main` 拉一个新分支，在 Dot 的云电脑里修改、运行相关测试，并用云 Chromium 打开修改后的页面。不要连接券商，不要提交真实交易，也不要合并或部署。

Pi 应先把实际听记结论转成可核验的验收项，再检查当前仓库状态和已有实现。对已在 `main` 的项目（例如 2026-10-26 生效日、17.90–19.12 元区间、100,000 股或 1,000,000 元门槛）不得重复造轮子。遇到听记与现有实现冲突时先停下并引用冲突，不擅自选择规则。

### 3. 让用户看页面，再创建 PR

Pi 先在云电脑 Chromium 展示最终页面，口头报告实际 URL、页面标题、改动点和测试结果。用户确认看到的内容后说：

> 页面我看到了。请创建这个分支的 GitHub Pull Request，把链接和测试结果告诉我；保持 PR 未合并。

PR 应以最新 `main` 为 base，包含本次必要代码与测试，列出听记依据和实际测试命令；不自动合并、不部署、不发交易委托。若没有新的代码差异，不创建空 PR；若同一差异已有未合并 PR，复用并报告该 PR，不再制造重复 PR。

## 节奏与超时处理

预计现场段落为 7–12 分钟，尚未通过完整实机流程计时，不能当作保证时长。下表是各阶段的提示性节奏；云端修改与测试可能占用 3–7 分钟，不能为赶时间跳过验证。会前至少做一次完整计时彩排：

| 阶段 | 建议用时 | 现场重点 |
| --- | ---: | --- |
| 拨通与中文提问 | 15–30 秒 | Dot 确认开始查询；没有长时间静默 |
| 查会议、听记、待办 | 30–60 秒 | 报真实来源、结论、负责人和截止时间 |
| 派工与审查仓库 | 30–60 秒 | 显示从最新 `main` 创建的分支和实际任务范围 |
| 修改与测试 | 3–7 分钟 | 投影云电脑实时操作；语音或任务进度用真实阶段状态更新 |
| 页面验收与 PR | 1–2 分钟 | 展示真实 URL/标题/页面，再创建未合并 PR |

如果单阶段超出 60 秒，Dot 应简短说明当前真实进度，用户可继续让它后台工作；不得播放预制成功话术、伪造进度或为了控时跳过测试。若总时长对领导场景仍太长，应在彩排后优化仓库启动/依赖缓存和任务目录准备，不预先完成代码修改来冒充现场执行。

## 可重复运行与复位

1. 日程、AI 听记和待办是用户的真实记录，整个演示过程只读；复位绝不删除或重建它们。
2. 每轮使用新的 Dot 对话、任务 ID 和云电脑任务目录。只有确认存在新的代码要求时，Pi 才从重新 fetch 的最新 `origin/main` 创建功能分支；不要把新任务目录误当作需要重复造一个功能分支。若同一要求的相同差异已有未合并 PR，可在干净任务目录重演分析、修改和测试，但最终复用该 PR 链接，不能重复开 PR。
3. 每轮从最新 `main` 开始，不回退 `main`、不 force-push、不清理整个租户 PVC。清理范围仅限已验证的本轮任务工作目录；当前还没有经公网 Chrome 验证的专用复位按钮，因此正式演示前需证明新任务会得到干净目录。
4. PR 保持未合并。若把 PR 合入 `main`，相同需求下次运行已不再是新改动；重演必须基于新的真实会议结论，或另行建立经过用户认可的独立演示仓库，不能把旧 main 当“最新 main”。若 PR 仍未合并且差异相同，复用它作为演示结果；新结论带来不同差异时，再从当时最新 `main` 拉新分支。
5. 屏幕截图和录屏保存在项目内 `artifacts/demo/mobile-secretary-bse/<run-id>/`。每张图标注阶段、时间、来源（真实公网 Chrome 或本地测试）；隔离 E2E 图不得标成公网验收图。完整验收后再将图集发送到用户的钉钉。
