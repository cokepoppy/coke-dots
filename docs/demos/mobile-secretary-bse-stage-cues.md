# 北交所会议秘书：会议室现场提示卡

这张提示卡用于手机 Chrome 语音通话现场演示。它配合 [`mobile-secretary-bse-review.md`](./mobile-secretary-bse-review.md) 使用；现场说辞必须跟着钉钉刚读取到的真实日程、会后 AI 听记和待办走。会前速记不能当作会议结论，证券应用中的数据是合成测试数据。

## 上台前 10 分钟

- 手机用 Chrome 打开 `https://codex.cokeagent.com/dots-demo/`，确认当前 Google 账号、Pi 内核和 Dot's computer 状态。先做真实手机麦克风输入和扬声器/耳机回放检查；电脑上的设备模拟不能代替手机验收。
- 镜像手机屏幕到会议室显示器。若手机画面无法同时让观众看清云电脑操作，使用已登录同一账号、同一工作区的第二个 Chrome 窗口展示 Activity/Computers。彩排确认两个画面显示的是同一个任务，避免现场切换登录或临时创建第二个任务。
- 核对真实会议已结束，并确认主持人在会议过程中按组织规则启动了 AI 听记/云录制，且本次会后记录已经生成并可读；日程结束本身不代表听记已产生。确认现有待办仍关联、证券仓库最新 `main`、同一需求是否已有未合并 PR、任务目录是本轮新建的。录屏和截图写到 `artifacts/demo/mobile-secretary-bse/<run-id>/`。
- 不改真实日程、听记或待办；不连接券商、不创建真实委托；不在演示前预先修改代码来冒充实时修复。Mac K3D 承载 Dots、DWS 和租户 Debian/Pi；VPS 只做隧道/反向代理。

## 现场流程（预估约 7–12 分钟；完整手机彩排计时前不对外承诺时长）

| 时间 | 演示者说/做 | 观众应该看到 |
| --- | --- | --- |
| 0:00–1:30 | 手机上打开 Dot 的 Call，等接通后说：“Dot，请只读查一下已经结束的北交所交易规则变更评审，读取实际会后听记和关联待办。用一分钟告诉我会议结论、待办负责人和截止时间。” | 手机上的小型通话界面；回答引用真实会后记录。会议尚未结束或会后听记未生成时，停在会前状态，不继续后续脚本。 |
| 1:30–2:00 | 听 Dot 概括真实结论。不要为同一问题重复发话；若需要补充信息，使用下一轮清楚限定要查的字段。 | 同一语音只产生一份转写和一个任务；回答对应同一会议及待办。 |
| 2:00–3:00 | 只有听记确有新产品要求时才说：“按你刚查到的会后听记和待办，检查证券移动交易页。只落实会议新确认且最新 main 还没有的要求；从刚 fetch 的 main 开分支，在 Dot 的云电脑里修改、测试，再打开页面给我看。不要连接券商、下单、合并或部署。” | Pi 接单；Activity 显示真实任务阶段。若 main 已实现全部内容，Dot 应报告无需改代码并结束此段，不制造 PR。 |
| 3:00–10:00 | 让通话保持可用，第二块屏展示同一任务的 Debian 云电脑。以屏幕上的真实 Activity 为准；不要假定 Dot 会定时语音播报，也不要重复提交原请求。 | 若确有代码缺口，观众看到仓库核对、分支、修改与测试；所有动作来自当前任务。实际时间视代码差异而定。 |
| 10:00–12:00 | Dot 报告测试结果和页面地址后，实际检查云 Chromium 页面。验收通过后说：“我验收通过。请把这个分支推到 GitHub 并创建 Pull Request，目标 main，保持未合并，不要部署。” | 展示真实页面、测试证据及未合并 PR；若无代码改动则不创建空 PR。 |

以上为排程估算，修改与测试阶段可能超过 7 分钟。若未能按时完成，保留真实任务并如实展示进度；不为赶时长跳过仓库核对或测试。Dot 当前不会保证每 30–45 秒语音播报；用 Activity 展示真实进展。

## 必须遵守的分支与结果规则

1. Pi 从本轮刚 fetch 的最新 `origin/main` 创建分支；不得从旧演示分支或旧任务目录继续。
2. 若会后听记没有新增要求，或要求已存在于 `main`，就做只读核验并结束，不制造无效修改/PR。相同要求已有未合并 PR 时复用原 PR；只有新结论产生不同代码差异时才新建分支和 PR。
3. 先让用户看到云电脑中的页面并验收，再创建 PR。PR 保持未合并；不部署。
4. 日程、听记、待办是复用的真实钉钉记录。每轮只新建 Dot 对话和任务，不克隆/修改这些业务记录。

## 一轮结束后重置

- 下一轮用新的 Dot 对话、唯一 `run-id` 和新云电脑任务目录；确认 Pi 当前检出的仓库为最新 `main`。不要清理整个租户 PVC，也不回退/force-push `main`。
- 保留上一轮工件与 PR 证据。若上一轮 PR 未合并且下一轮需求相同，复用该 PR，不重复推送相同差异或开重复 PR。
- 每轮保存通话界面、真实纪要摘要、Activity 进度、云电脑查阅/修改/测试、修复页面、PR 未合并状态的截图。文件名带序号和时间，注明截图来自公网 Chrome；完整验收后再发送到用户钉钉。

## 现场中止条件

- 会议尚未结束、真实会后听记不可读、听记与当前代码冲突且需要人判断、Pi 不可用、云电脑无法打开、测试失败或通话没有可懂的中文音频：如实说明并停在当前阶段。不要展示过时工作区冒充本轮结果，不要创建空 PR。
- Chromium 当前曾显示 `--no-sandbox` 警告。若现场仍显示，先记录截图并评估是否影响观众；不要临时删除启动参数或重启云电脑。该环境缺少 user namespace sandbox 支持，修复需独立构建并验证镜像与租户回滚。
